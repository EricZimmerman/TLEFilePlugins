# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Plugins for Timeline Explorer (TLE, the `timelineexplorer` repository): each one turns a CSV (or text) format into typed rows. TLE loads every DLL in its `Plugins` folder and creates every `IFileSpec` type in them; it references `ITLEFileSpec` and `TLEFileTimelines` itself, and ships CsvHelper, Serilog and the other dependencies.

- `ITLEFileSpec` (`netstandard2.0`): `IFileSpec` (ExpectedHeaders, DataList, TaggedLines, InternalGuid, ProcessFile) and `IFileSpecData` (Line, Tag). Its interface is TLE's contract: don't change it.
- Plugin projects (`netstandard2.0`, one assembly each): `TLEFileEZTools` (Eric's tools), `TLEFileMisc` (third-party tools: Chainsaw, Hayabusa, BrowsingHistoryView, ...), `TLEFileKAPE`, `TLEFileMicrosoft`, `TLEFileTimelines`, `TLEFileTzWorks`, `TLEFileGenericCsv` (any other CSV/TSV; detects `,` tab `|` `;` with CsvHelper's separator detection, after a PowerShell #TYPE line, PR #18; .tsv is always tab).
- **Matching**: TLE reads the file's first line and takes the first plugin whose `ExpectedHeaders` (a case-insensitive set of whole header lines) contains it; else GenericCsv. When a tool adds columns, **add its new header line to the same plugin and keep the old ones** (files from older tool versions), and add the new properties at the end of the data class (before Line/Tag) and to its `ToString` (TLE searches it). A new CSV gets a new plugin with a new `InternalGuid` (unique across all plugins; the tests check).
- **Variable headers**: iisGeolocate's CSVs are the IIS log's own `#Fields` plus `GeoCity,GeoCountry`, so `IisGeolocate` lists the IIS 6 and 7-10 defaults, every standard field, and variants seen in test logs (W3C names mapped to properties; `-` in a number field is null, `W3CNumberConverter`); another field list opens as generic, so add its header line. SQLECmd writes one CSV per map query (columns from the map's SQL, then SourceFile): only the ActivitiesCache map's three have plugins (`SqleActivitiesCache`, `SqleActivityPackageId`, `SqleActivityOperation`); the others open as generic.
- **CsvHelper 34** (2026-11; 33 before): every data class read with GetRecords/GetRecord is a `[CsvRecord] public partial class` (the source generator writes its mapper; the plugin projects reference CsvHelper themselves, since analyzers are not transitive). Attributes replace the old ClassMaps: `[CsvColumn("SI<FN")]`, `[CsvConverter(typeof(...))]` (`ICsvConverter<T>`), `[CsvIgnore]` on Line, Tag and Color. TLE ships CsvHelper's **net10.0** build and the plugins are **netstandard2.0**, so:
  - `CsvReaderOptions` can't be built with object initializers or `with` in plugin code: the init setters' signatures name CsvHelper's own IsExternalInit in its netstandard2.0 build and the runtime's in the .NET one (MissingMethodException). Use `CsvLoader.Options.With((nameof(CsvReaderOptions.X), value), ...)` (reflection on a copy).
  - Generic code must call `TryParse<T>`/`Parse<T>` with concrete types (the .NET build constrains T to ISpanParsable); `EmptyIsDefaultConverters` has one converter per type for that reason.
  - The tests (net10.0) run the plugins on the net10.0 CsvHelper, as TLE does: they catch both.
- **`Shared/CsvLoader.cs`** (linked into each plugin project, GenericCsv too, so nothing new ships): `CsvLoader.Load<T>(filename, DataList, TaggedLines, options, fixup)` does what every plugin repeated, plus: every member of a CsvLoader data class is `[CsvColumn(Optional = true)]` (a column the file doesn't have keeps its default: older header versions), columns match ignoring case (CsvHelper 34 matches exactly, then ignoring case and whitespace; TLE matches headers ignoring case), an empty value in a non-nullable value column is its default (assembly-level `[assembly: CsvConverter]` converters for bool, the numbers, DateTime, DateTimeOffset, Guid, TimeSpan; one empty value failed the whole file), bad quoting is recovered from, a field past the end of a short record is empty, tagged lines in a HashSet, no ListChanged event per row, the raw record (`csv.Current.ToString()`) only built for debug messages. `CsvLoader.Options`: comma separated (34 detects the separator by default: CsvLoader must not), PoolStrings. Times are read as written (CsvHelper 34 keeps a time ending in Z as UTC; 33 converted it to local time). `CsvLoader.ParseTime` and its converters (`ParseTimeConverter`, `UniversalParseTimeConverter`, `NoZParseTimeConverter`, `LenientDateTimeConverter`) for the plugins whose times need it (empty or bad text is MinValue/null). Plugins that parse by hand (TzWorks, Timelines, DensityScout, AnalyzeMft, Shimcache*, Sigcheck*, Autoruns, ConvertPSHistoryToCSV) don't use Load; their columns are not Optional (a missing one fails the file, as before). Those that read columns by name match them ignoring case like CsvLoader (a lower-case L2T header failed); Psort and SuperTimeline use `GetOrNull` (null for a field a short record lacks, as 33 gave). They use `CsvLoader.QuietList<T>(DataList)` (no ListChanged event per row) and check `Log.IsEnabled(LogEventLevel.Debug)` once before logging each row's raw record.
- **String pooling**: one string for a value repeated in many rows is about half the retained memory of a large file (measured 2026-10-20). PoolStrings is on, but CsvHelper 34 stops pooling a column where most values are new (MFTECmd's FileName/ParentPath, EvtxECmd's payloads): `PooledStringConverter` (assembly-level, every string member of a [CsvRecord] type) and `StringPool` (GenericCsv, Psort, SuperTimeline) pool every value up to 1024 characters for one file. Measured 2026-11-20, old 33 vs 34: EvtxECmd CSV of 1.49 M rows (2.2 GB) 9.1 s / 3,301 MB retained -> 4.1 s / 2,729 MB; MFTECmd $MFT CSV 313 K rows 1.55 s / 136 MB -> 0.76 s / 128 MB; the same as a generic CSV 3.2 s / 231 MB -> 2.6 s / 223 MB.
- **Layouts** (`Layouts/Default/<namespace>.<class>.layout`, DevExpress grid layouts): TLE restores `Layouts\<name>.layout.local` (the user's) or `Layouts\Default\<name>.layout`; columns not in a layout are added at the end. Every EZ Tools plugin has one and every layout has all its plugin's columns (tests). The files came from Eric's TLE folder in 2026-10; `CopyPlugins.ps1 -Layouts` copies them.

## Commands

The SDK is pinned in `global.json` (.NET 10). Tests use NUnit 5 + FluentAssertions 7 (pinned to `[7.2.2,8.0.0)`, since 8.x requires a commercial license).

```bash
dotnet build TLEFilePlugins.slnx -c Release
dotnet test TLEFilePlugins.slnx -c Release          # CI (test.yml)
pwsh ./CopyPlugins.ps1 -Out <TLE>\Plugins -Layouts <TLE>\Layouts [-Build]
pwsh ./CopyPlugins.ps1 -ImportLayouts <TLE>     # TLE's saved layouts (*.layout.local) into Layouts/Default
```

## Tests (`TLEFile.Test`, net10.0)

- `PluginTests`: unique InternalGuids; no header line claimed by two plugins; for every plugin (except the hand-parsed ones) and each of its header lines, a synthesized file (typed values by property name) loads 3 rows and tags; `TestFiles/CurrentHeaders.tsv` (the header lines of every CSV the 2026.10 tools write; header lines only, no data) all go to a plugin; layouts match plugins and have every column; every layout starts with Line, then Tag (`LayoutsStartWithLineThenTag`); `RealOutputs` (`[Explicit]`, `TLE_CSV_DIR`) loads real tool outputs.
- `LoaderTests`: older header versions, empty values, header case, times as written, GenericCsv delimiters.
- When a tool changes its CSV: run it, add its header line to `CurrentHeaders.tsv`, then to the plugin, then the layout.

## Versioning and release

No package or version: TLE ships the plugin DLLs (built here, copied to its `Plugins` folder) and the layouts.
- `Directory.Build.props`: pdbs are embedded in the assemblies (`DebugType` embedded, `EmbedUntrackedSources`) and Release builds set `ContinuousIntegrationBuild` (source paths `/_/...`, not this machine's), so stack traces (Exceptionless) have file and line numbers and no .pdb file ships (CopyPlugins copies only the dlls). Don't add `DebugType` to project files.
- **`Layouts/Default` is the source of truth for TLE's default layouts** (Eric, 2026-10). To make a layout saved in TLE the default, run `CopyPlugins.ps1 -ImportLayouts <TLE>` (copies each changed `Layouts\<namespace>.<class>.layout.local` here as `<namespace>.<class>.layout`, skips names with no plugin, reports a saved filter, find text, sorting or grouping), run the tests and commit. `PluginTests` fails for an EZ Tools plugin without a layout or a layout without a plugin.
- `Build-ZimmermanTools.ps1` (get-zimmermantools) runs `CopyPlugins.ps1 -Build` and stages the plugin DLLs in Timeline Explorer's `Plugins` and these layouts in its `Layouts\Default`: every plugin project in the solution ships.
